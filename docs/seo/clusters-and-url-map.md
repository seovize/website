### Technical-SEO page gate (Phase 6 requirement: "only if SERP research confirms separate intent")

Evidence for a standalone `/services/technical-seo` page: **insufficient**. No GSC signal, and WebSearch did not surface a distinct "technical-SEO-only" agency category separate from general SEO agencies — technical SEO is consistently sold as a component of a broader SEO retainer, not a standalone product, across the agencies observed. Per the explicit instruction "do not create a new page when an existing page can satisfy the same intent," technical SEO stays a strengthened section within `/services/seo` (it already has a "Google Search Console management," Core Web Vitals, and technical-audit deliverable). **Decision: Defer / do not create.**

## Cannibalization report

Three **monitor-level** risks identified — none are currently confirmed head-to-head ranking conflicts (no GSC evidence either page is suppressing the other, since neither has meaningful US impressions yet), but the content overlap is real enough to flag before Phase 6 implementation:

1. **`/services/seo` vs `/services/semantic-seo`.** Both pages currently discuss schema markup, featured snippets, and topical authority in overlapping language (confirmed during Sprint 2.1's methodology-claim correction pass — both pages needed nearly identical fixes to the same claims). **Recommendation:** `/services/seo` = the general/broad commercial offer (technical + local + content + semantic, positioned as the default entry point). `/services/semantic-seo` = the specialist deep-dive for buyers who already searched the specific term. `/services/seo` should link to `/services/semantic-seo` as "go deeper," not compete for the same head terms. Differentiate title tags and H1s more sharply in Phase 6.
2. **`/services/local-seo` vs `/locations/texas/seo-services`.** Both touch Google Business Profile and service-area strategy. **Recommendation:** `/services/local-seo` = national local-SEO product page (methodology, pricing). `/locations/texas/seo-services` = Texas-specific hub linking out to the 4 (soon 5) city pages. Keep GBP-methodology content on `/services/local-seo` only; the Texas hub should summarize and link, not duplicate.
3. **`/locations/texas/seo-services` (state hub) vs `/locations/texas/dallas-seo` etc. (city pages).** Standard hub-and-spoke structure — defensible as long as the hub stays state-level/comparative and city pages stay city-specific. No changes needed beyond what's already in place; flagged for monitoring only.

No **confirmed** cannibalization (two URLs actively ranking for and splitting the same query) was found, because GSC currently shows real ranking data for only the Dallas SEO cluster, which maps cleanly to one URL.
